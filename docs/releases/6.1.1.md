# InnoNetwork-Protobuf 6.1.1

Release-Status: Ready

## Breaking changes

- Pins the published core 6.1.1 encoded-request contract exactly. Adapter publication remains pending.
- Replaces the old ProtobufAPIDefinition protocol/protobufRequest with the
  default-enabled @ProtobufAPIDefinition macro and public EncodedRequest factories.
- Adds ordinary body+query, optional Message bodies and explicit HTTP no-content;
  all named endpoints use core EncodedAPIDefinition and its existing operation engine.
- Removes custom Empty Message and implicit HTTP empty decoding; use generated
  Google_Protobuf_Empty or core EmptyResponse/noContent according to server semantics.
- Standard application/protobuf by default, strict response media validation,
  explicit legacy/missing-header compatibility and caller-chosen byte/depth limits.
- SwiftProtobuf minimum 1.38.1; module and both product names are preserved.
- All runtime execution uses core policy, without SPI or a second task/retry engine.

See [migration](../MIGRATION_6_0.md) and [implementation evidence](../IMPLEMENTATION_6_0.md).

## Versioning

This is the first published adapter 6.x release, a breaking upgrade from 3.0.1.
The number is coordinated with Core 6.1.1; it does not imply patch compatibility
with adapter 3.x. Existing adapter 3.0.1 and all Core tags remain unchanged.

## Release gates

- Core exact 6.1.1 is published and verified at `44e4ca28c50c03f817231a077c0f3bdfdbc859c8`.
- Review this final version/documentation change and rerun the exact PR head in
  the release-validation lane, including fresh-scratch TSAN on both toolchains.
- Merge only after successful exact-head validation; confirm main CI, then create
  the approved annotated 6.1.1 tag on the reviewed main commit.
- The Release workflow must validate that exact remote tag object and commit,
  all consumers, both toolchains, fresh TSAN, and platform builds.
- Publication requires committed Ready notes, main ancestry, an existing
  annotated tag, and an explicit `publish: true` run. Validation never creates tags.
- After publication, verify a clean external consumer with remote-only adapter
  6.1.1 and Core exact 6.1.1 and check the resolved revisions.

Physical-device E2E has not been run; SDK compilation is not device validation.
Historical SPI evidence does not satisfy these new-contract gates.
