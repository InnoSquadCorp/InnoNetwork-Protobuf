# InnoNetwork-Protobuf 6.0.0 Release Notes

## Status

InnoNetwork `6.0.0` is published. This adapter release remains a draft until
its own reviewed-commit, CI and publication gates pass. Local compatibility
validation is separate from publication; see [the evidence record](../COMPATIBILITY_6_0.md).

## Summary

InnoNetwork-Protobuf 6.0.0 realigns the protobuf adapter with InnoNetwork 6.0's
explicit authentication, structured failure, and generated-client support
contracts. Its public protobuf surface remains focused and source-compatible
apart from the endpoint authentication witness introduced on the development
line.

## Highlights

- Requires InnoNetwork `6.0.0..<7.0.0`
- Keeps binary request execution behind the narrow
  `GeneratedClientSupport` SPI
- Requires every protobuf endpoint to declare its session-authentication intent
- Aligns deployment floors with InnoNetwork 6.0
- Enforces Swift 6 language mode across production and validation targets
- Uses the `InnoNetwork-Protobuf` repository/package/product name, while
  preserving the `InnoNetworkProtobuf` module and compatibility product
- Retains a validated local dependency override for coordinated pre-tag testing
- Verifies the published core's authentication, binary replay, cancellation,
  structured decoding errors and safe POST retry boundaries
- Runs the independent consumer through an actual in-memory protobuf request
  and response, rather than only constructing the client

## Release Order

1. Publish and verify InnoNetwork `6.0.0`.
2. Resolve and validate InnoNetwork-Protobuf without
   `INNONETWORK_LOCAL_PATH`.
3. Validate the local adapter from an independent consumer using the remote core.
4. Complete exact-commit CI and publish the annotated InnoNetwork-Protobuf `6.0.0` tag.
5. Validate a clean external consumer against both published remote tags.
